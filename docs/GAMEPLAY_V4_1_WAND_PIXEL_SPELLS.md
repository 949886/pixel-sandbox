# Gameplay V4.1 — Wand & Pixel Spells

V4.1 moves wand tuning out of `Player.gd` and establishes the first data-driven spell pipeline while keeping the V3.x streaming/simulation/collision/rendering internals frozen.

## Runtime pipeline

```text
Player input
  -> WandController
  -> WandDef
  -> selected SpellDef
  -> CastContext
  -> GameplayEffect[]
  -> ProjectileEffect
  -> ProjectileDef
  -> GameplayProjectile
  -> impact GameplayEffect[]
  -> actor / pixel world
```

Gameplay code does not need to know about simulation blocks, visual sectors or collision-sector revisions.

## Starter wand

The starter wand contains four explicit architecture-validation spells:

1. **Spark Bolt** — fast, accurate, 10 projectile damage, tiny 1.5 px terrain chip.
2. **Dig Bolt** — 4 damage, 6 px terrain carve, amber debris-like pixel impact.
3. **Fire Bolt** — 7 fire damage, Burning status, tiny terrain chip, deposits native Fire element ID 5 into nearby air pixels.
4. **Bomb** — slow arcing projectile with gravity; explodes on contact or timeout, deals radial explosion damage and removes a 22 px terrain circle.

Desktop selection uses `1`–`4` or mouse wheel. Left mouse continues to cast. Mobile keeps casting the currently selected spell; a dedicated mobile spell selector can be added with inventory UI rather than extending the old touch pad.

## Pixel spell visual language

The VFX deliberately avoids filtered projectile textures and smooth circle particles. `GameplayProjectile` and `PixelSpellVFX` render hard `draw_rect()` pixels snapped to integer positions:

- projectile core: 1–4 px square depending on spell;
- discrete world-space trail samples instead of a continuous line;
- alternating primary/secondary color pixels;
- small perpendicular trail jitter;
- muzzle chip burst;
- impact fragments with short lifetimes and optional gravity;
- Bomb adds a larger procedural square-fragment explosion burst.

This aims for the same *kind* of simulation-adjacent, low-resolution visual language associated with pixel sandbox spell games without copying Noita's textures, sprites, exact particle assets, or effect art.

## GameplayEffect foundation

Implemented effect resources:

- `ProjectileEffect`
- `DamageEffect`
- `TerrainEraseEffect`
- `IgniteEffect`
- `SpawnMaterialEffect`
- `ExplosionEffect`

New effects can be composed without creating a new projectile class for every spell.

## Pixel world writes

`WorldGameplayService` now exposes two deliberately small write APIs:

- `set_element_id_at_world_position()`
- `paint_material_circle()`

`paint_material_circle()` is capped at 12 px radius and is intended for small residues such as fire sparks, not bulk generation. Large destructive operations still use the existing native `erase_material_circle()` path.

## HUD

Player HUD now includes current wand mana and selected spell. Mana is owned and regenerated by `WandController`; death/respawn resets it.

## Validation

```bash
python validate_gameplay_v4_1.py

```

With a Godot executable:

```bash
godot --headless --path game --scene res://tests/GameplayCombatSmokeTest.tscn
```

The development container used for this patch does not provide a Godot executable, so final parser/physics/render runtime validation still belongs on a machine with Godot 4.x and the native extension available.
